# Data Model for Competitor Intelligence

Defines the YAML/JSON data structures used by the competitor intelligence system.

## Competitor Registry (`competitors.yaml`)

```yaml
competitors:
  - id: company_openai
    name: OpenAI
    website: https://openai.com
    github: openai
    priority: high          # high | medium | low
    products:
      - ChatGPT
      - GPT-4
      - Sora
    sources:
      website: true
      github: true
      news: true
      youtube: true
      twitter: true
      linkedin: true
      reddit: true
    created_at: "2026-09-16T07:40:56.488975"
```

### Fields

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `id` | Yes | string | Unique identifier, generated as `company_<name-slug>` |
| `name` | Yes | string | Display name of the company |
| `website` | No | string | Company website URL |
| `github` | No | string | GitHub organization/username |
| `priority` | No | string | `high`, `medium`, or `low` — affects collection frequency |
| `products` | No | list[string] | Known products/offerings |
| `sources` | No | object | Per-source enable flags (default: all true) |
| `created_at` | Auto | ISO datetime | When added to registry |

### ID Generation

The ID is generated by:
1. Lowercase the name
2. Replace spaces and hyphens with underscores
3. Truncate to 30 characters
4. Prefix with `company_`
5. If duplicate, append `_1`, `_2`, etc.

Example: "OpenAI" → `company_openai`

### Merge Behavior

When adding a competitor that already exists (by name, website, or GitHub handle), the existing entry is removed first, then re-added with fresh data. This handles the case where product lists or priorities need updating.

## People Registry (`people.yaml`)

```yaml
people:
  - id: person_sam_altman
    name: Sam Altman
    company: company_openai        # Competitor ID this person is associated with
    role: CEO of OpenAI
    sources:
      x: true
      linkedin: false
      news: true
      youtube: false
    added_at: "2026-09-16T08:30:00.000000"
```

### Fields

| Field | Required | Type | Description |
|-------|----------|------|-------------|
| `id` | Yes | string | Unique identifier, `person_<name-slug>` |
| `name` | Yes | string | Person's name |
| `company` | No | string | Associated competitor ID (or empty for independent figures) |
| `role` | Yes | string | Job title / role description |
| `sources` | No | object | Which sources to monitor (default: x + news only) |
| `added_at` | Auto | ISO datetime | When added |

### ID Generation

Same pattern as competitors: `person_<name-slug>` with numeric suffix for duplicates.

## Snapshots

Stored per entity per source type:

```
snapshots/
  {entity_id}/
    {source_type}/
      current.json          # Latest snapshot (always updated)
      {timestamp}.json      # Historical snapshots (never deleted)
```

### Snapshot Structure

```json
{
  "timestamp": "20260916T074448Z",
  "content": "<collected content, max 50000 chars>",
  "metadata": {
    "source": "jina_reader",
    "url": "https://openai.com"
  },
  "content_hash": "<sha256 of content>"
}
```

## Events (`events/events.jsonl`)

Line-delimited JSON. Each line is one event.

```json
{
  "event_id": "20260916T074448a1b2c3d4",
  "entity_id": "company_openai",
  "entity_name": "OpenAI",
  "event_type": "product_launch",
  "detected_at": "2026-09-16T07:44:48.123456",
  "source_type": "website",
  "source_url": "https://openai.com",
  "old_value": "GPT-4",
  "new_value": "GPT-5",
  "confidence": "high",      # high | medium | low
  "description": "GPT-5 launched",
  "event_sources": ["website"],
  "status": "new"
}
```

### Event Types

| Category | Types |
|----------|-------|
| Product | `product_launch`, `product_update`, `feature_added`, `feature_removed` |
| Pricing | `pricing_change`, `pricing_plan_change` |
| People | `hiring_change`, `job_opened`, `job_closed`, `leadership_change` |
| Corporate | `funding`, `acquisition`, `partnership`, `company_news` |
| Technical | `github_release`, `github_activity`, `technology_signal` |
| Content | `website_change`, `documentation_change`, `blog_post`, `social_post`, `youtube_video`, `reddit_discussion` |
| Market | `market_news`, `customer_announcement` |

## Alert State (`alerts/alert_state.json`)

```json
{
  "alerted": {
    "company_openai:pricing_change": "2026-09-16T10:30:00.000000",
    "company_anthropic:product_launch": "2026-09-16T09:15:00.000000"
  }
}
```

Each key is `{entity_id}:{event_type}`, value is ISO timestamp of last alert sent. The system checks this before sending new alerts and skips if less than 24 hours have passed.

## Source Health (`source_health.json`)

```json
{
  "company_openai": {
    "website": {
      "status": "working",
      "last_checked": "2026-09-16T07:54:07.255244",
      "message": ""
    },
    "github": {
      "status": "working",
      "last_checked": "2026-09-16T07:54:08.002972",
      "message": ""
    },
    "news": {
      "status": "degraded",
      "last_checked": "2026-09-16T07:54:08.003519",
      "message": ""
    }
  }
}
```

### Status Values

| Status | Meaning |
|--------|---------|
| `working` | Source collected successfully |
| `degraded` | Partial success or fallback used |
| `failed` | Source collection failed |
| `unknown` | Never checked |

## Aliases

The entity resolver maintains an in-memory alias map (not persisted) from names, domains, GitHub handles, and product names to competitor IDs. This enables fuzzy resolution when users ask about "Claude" (resolves to Anthropic) or "GPT-4" (resolves to OpenAI).

## Design Notes

- All IDs are deterministic from the name — this makes cross-referencing stable across sessions
- Priorities drive collection frequency: high-priority competitors are collected every 6 hours
- The `sources` dict allows per-competitor customization (e.g., a company with no GitHub can have `github: false`)
- Snapshots are append-only — `current.json` is overwritten, historical snapshots are never deleted
- Events are append-only — the JSONL format allows easy line-by-line parsing and time-range filtering
