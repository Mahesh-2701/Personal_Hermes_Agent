# Website Competitive Intelligence

Automatically improve how you approach website creation, redesign, rework, and major UI/UX changes through structured market and competitor research.

## Core Objective

Whenever the user asks to:
- create a website / build a website
- redesign a website / rework a website / improve a website / rebuild a website / modernize a website
- create a landing page / create a SaaS frontend
- improve an existing website's UI/UX / redesign a product experience
- build a website for a business / product / startup

**Do NOT blindly start coding.**

1. Understand the project.
2. Determine whether competitive/reference research would materially improve the result.
3. Perform competitive and design intelligence research before implementation for meaningful website work.

---

## 1. Understand the Project

Before researching competitors, inspect the available project context.

Determine:
- What the product/business is
- What the website is supposed to accomplish
- Target users & primary user journeys
- Main conversion goal
- Product category & industry
- Geographic market if relevant
- Existing brand identity & design system
- Existing technical stack & pages/components
- Existing UI/UX problems, constraints, and required features

If this information already exists in the project, inspect the project instead of asking unnecessary questions. Only ask questions when missing information materially affects the research or implementation.

---

## 2. Determine the Website Category

Classify the website before searching (e.g., SaaS, AI product, developer tool, portfolio, agency, e-commerce, fintech, healthcare, education, marketplace, social platform, B2B/B2C software, startup landing page, dashboard, documentation, community, media/content, local business). Use the category to guide competitor discovery.

---

## 3. Competitor Discovery

Identify relevant websites to research:
1. Direct competitors
2. Successful products in the same category
3. Industry leaders & strong UX references
4. Websites targeting similar users with similar business/conversion models

Target approximately 3–5 strong direct competitors and 2–3 high-quality design/UX references (adjusted for project complexity).

---

## 4. Use Firecrawl

Use the available Firecrawl toolset (`firecrawl search`, `firecrawl scrape`, etc.) to collect structured information from competitor/reference websites:
- Page structure, navigation, hero section, headlines, subheadings, CTA patterns
- Feature presentation, product positioning, social proof, testimonials
- Pricing presentation, FAQ structure, footer structure, content hierarchy
- Information architecture, conversion flow, trust signals, forms
- Relevant copy patterns and SEO/content structure

Crawl targeted relevant pages rather than indiscriminate full-site crawls.

---

## 5. Competitive Intelligence Analysis

Analyze researched competitors across:
- **Positioning:** Value proposition, target audience, promises.
- **UX:** Entry points, primary user journeys, time-to-value, emphasized actions.
- **Information Architecture:** Pages, organization, prioritization.
- **UI Patterns:** Hero layouts, navigation, cards, grids, tabs, pricing tables, testimonials, screenshots, interactive demos, forms, FAQs.
- **Conversion:** Primary/secondary CTAs, signup/demo/pricing flows, trust signals.
- **Content:** Messaging hierarchy, tone, headlines, feature descriptions.

---

## 6. Extract Patterns, Not Designs

Never copy a competitor's design or assets. Instead, extract reusable principles and patterns.

- *Bad:* "Copy competitor X's hero section."
- *Good:* "Competitors in this category consistently place a concise value proposition, product visualization, and primary CTA above the fold. Use this pattern if it fits our product."

---

## 7. Create a Research Summary

Before implementation, produce a concise internal research summary covering project understanding, competitors researched, common patterns, best UX/content/conversion patterns, weaknesses observed, opportunities, and recommended direction.

---

## 8. Convert Research Into an Implementation Plan

Translate findings into concrete recommendations for our website:
- Recommended Information Architecture
- Recommended Hero & UX
- Recommended Design Direction & Differentiation

---

## 9. Preserve Project Identity & Boundaries

Competitive research must NOT overwrite existing brand identity, design system, intentional UX decisions, or component architecture unless explicitly requested. Never copy competitor text, branding, illustrations, proprietary code, logos, testimonials, or images.

---

## 10. Research Depth Matches Task

- **Tiny change** (e.g., button color): No research.
- **Small UI improvement** (e.g., pricing card): Lightweight research if useful.
- **New page / landing page**: Perform competitive research.
- **Complete redesign / new product website**: Comprehensive research.

---

## 11. Existing Website Rework

When reworking an existing website:
1. Inspect current routes, components, design system, styles, UX, content, responsive behavior, and architecture.
2. Compare current implementation with relevant competitors.
3. Identify what is good, what should remain, what should change, what is missing, and what is unnecessarily complex.

---

## 12. Mobile, Accessibility & Technical Analysis

- Evaluate responsive layouts, mobile navigation, touch targets, typography, contrast, keyboard navigation, and semantic structure.
- Investigate publicly observable technical characteristics (framework patterns, performance, metadata, asset loading, structured data) while distinguishing observed facts from inference.

---

## 13. Implementation Workflow

Understand → Inspect existing project → Classify website → Discover competitors → Research with Firecrawl → Analyze patterns → Identify opportunities → Create design/UX direction → Plan implementation → Implement → Test → Review against research → Explain what learned.

---

## 14. Explain What You Learned

After meaningful website work, explain:
1. **What we learned:** Market patterns discovered.
2. **What we adopted:** Principles used.
3. **What we rejected:** Competitor patterns intentionally not used and why.
4. **What we built:** Changes made.
5. **Why:** Engineering/product/UX reasoning.
6. **Verification:** How tested.
